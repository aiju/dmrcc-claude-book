Before looking at any routine in detail it is worth seeing the whole compiler at once: what programs it consists of, what each one reads and writes, and what the machine it targets looks like. This chapter is that overview. Nothing in it needs to be memorised; the later chapters come back to every point.

From cc x.c to a.out

The command cc is not the compiler. It is a small program ([[cc.c:50-219]]) that runs the real compiler, which is three separate programs called c0, c1 and c2 kept in /lib, followed by the assembler as and the link editor ld. The passes talk to each other through temporary files in /tmp whose names cc invents ([[cc.c:118-135]]).

In order:

  1. Preprocessing. If, and only if, the source file begins with #, the routine expand inside cc handles #define, #include and conditional compilation and writes the result to a temporary file ([[cc.c:235-290]]). Otherwise the source goes straight to c0. Chapter 2.
  2. c0 reads C. It does all the lexical analysis, parsing, type checking and storage allocation, and writes two files: one holding the program as a sequence of expression trees and simple commands in a compact binary form, and one holding the text of string constants. It knows nothing about the instruction set. Chapters 3 to 8.
  3. c1 reads the trees back, improves them, and turns them into PDP-11 assembly language by matching them against tables of code templates. Chapters 9 to 12.
  4. c2, run only if you ask for it with -O, reads the assembly language and improves it: removing jumps to jumps, merging identical code, remembering what each register holds. Chapter 13.
  5. as assembles, and ld links the result with the start-up code crt0.o and the C library.

With -S, cc stops after the assembly language and leaves it in x.s ([[cc.c:62-65]], [[cc.c:163-164]]), which is how the output shown throughout this book was captured. With -P it stops after preprocessing and leaves the result in x.i.

Why three programs

A PDP-11 program could address at most 64 kilobytes, and on the smaller machines Unix ran on, instructions and data had to share that space. The compiler had to fit, together with its symbol table and the tree for the largest expression it could meet. Splitting the work into separate programs means that each one needs only its own code and data in memory. c0 never holds the code tables; c1 never holds the symbol table. The intermediate files are the price.

The split also falls along a sensible line. Everything that depends on the syntax of C is in c0. Everything that depends on the instruction set is in c1, and much of that is in the code tables rather than in C. Retargeting the compiler meant rewriting c1 and its tables and leaving c0 nearly alone, and versions of this compiler were produced that way for other machines. Steve Johnson's Portable C Compiler, which replaced it a few years later, made the same division its central design principle.

Each pass is also a separate program in a stronger sense: they share no code. The pass headers c0h.c and c1h.c each define the operator numbers, and the two copies must agree, since the operators are the vocabulary of the intermediate file. Both passes also carry their own copy of the operator property table opdope ([[c05.c:16]] and [[c13.c:1]]), and the copies are not identical, because c1 invents operators of its own.

The PDP-11 in a few pages

Almost everything the compiler does in its second and third passes is shaped by the machine, so here is enough of it to read the generated code. Numbers in PDP-11 assembly language are octal unless they end with a decimal point, and the compiler prints them in octal ([[c11.c:615-625]]). This book follows that convention inside code and uses decimal in the text.

Registers and memory

The machine has eight 16-bit general registers, r0 to r7. Two are special: r7 is the program counter, written pc, and r6 is the stack pointer, written sp. The stack grows toward lower addresses. Memory is addressed in bytes, but most instructions operate on 16-bit words, which must be at even addresses. A word is stored low byte first.

The C compiler assigns the remaining registers as follows. r5 is the frame pointer: it points into the current function's stack frame, and locals and arguments are addressed relative to it. r4, r3 and r2 hold register variables, allocated from r4 downward ([[c03.c:280-285]]). Whatever is not used for register variables, together with r0 and r1, is available to hold temporary values while evaluating an expression. A function's result is returned in r0, or in r0 and r1 for a long.

Addressing modes

Every operand is specified by a three-bit mode and a register. The eight modes are the heart of the machine, and the reason the PDP-11 fitted C so well: several C expressions map onto a single operand.

ModeSyntaxMeaningAs C
0r3the register itselfr
1(r3)the word the register points at*r
2(r3)+as mode 1, then add 2 (or 1 for a byte) to the register*r++
3*(r3)+the register points at a pointer; use that, then add 2**r++
4-(r3)subtract 2 (or 1) from the register first, then as mode 1*--r
5*-(r3)subtract 2, then use the pointer the register points at**--r
612(r3)the word at the register plus a constantr[5], p->m
7*12(r3)the pointer at the register plus a constant*p->m

Modes 2, 3, 6 and 7 applied to the program counter give four more useful forms. Mode 2 with pc reads a constant stored right after the instruction and is written $12. Mode 6 with pc addresses memory relative to the current instruction and is written as a plain name, _x. Mode 3 and mode 7 give indirect versions of these, written *$_x and *_x. So * in PDP-11 assembly means one extra level of indirection, which is exactly what it means in C. The compiler's operand printer pname ([[c11.c:36-112]]) uses the same character for both.

Instructions

Two-operand instructions are written source first, destination second: mov a,b copies a to b, and add a,b adds a to b. Nearly every instruction also has a byte form with a b suffix. The instructions the compiler uses most are these.

InstructionEffectNotes

cmp a,bset condition codes from a - bnote the order: source minus destination

jbr L, jeq L, …jump, or jump if a condition holdsnot machine instructions; see below

Three of these constrain the compiler more than the others. bic is the only way to do a logical AND, so the compiler rewrites a & b as a bit clear of the complement, a &~ (~b), and folds the ~ into the constant when there is one, which is why you will see bic $-10,r0 where you might expect an AND with 7 ([[c12.c:39-47]]). ash shifts right only by a negative count, so right shifts are rewritten as left shifts by the negated amount ([[c12.c:139-150]]). And mul and div need registers with particular parity, which is the reason for the routine oddreg ([[c11.c:263-282]]).

The conditional jumps come in two families. jlt, jle, jgt and jge test the result as a signed number; jlo, jlos, jhi and jhis (lower, lower or same, higher, higher or same) test it as unsigned. The compiler uses the unsigned family to compare pointers ([[c1t.s:70-73]]). The names beginning with j are understood by the assembler, which turns each into a short branch if the target is close enough and into a branch around a jmp otherwise. This saved the compiler from having to know how long its own code was.

Floating point

Some PDP-11s had a floating-point unit with six more registers, fr0 to fr5, and instructions such as movf, addf and mulf. Its mode bits decide whether it works in single or double precision, and C sets it to double. movof and movfo convert between float in memory and double in a register. Many machines, including the PDP-11/40, did not have the unit, and cc -f links in a simulator for it instead. The compiler itself is affected too, as chapter 4 explains.

Calling a function

Arguments are pushed onto the stack from right to left, so the first argument ends up nearest the top. Then the function is called with jsr pc,f, which pushes the return address. The first thing every compiled function does is jsr r5,csv, and the last thing it does is jmp cret. These two routines live in the C library. Here they are in full.

[[src:csv.s:6-22]]

jsr r5,csv pushes the old r5 and puts the return address, which points back into the function, in r5. csv moves that address to r0, points r5 at the saved r5, saves the three register-variable registers, reserves one more word with tst -(sp), and jumps back. cret undoes it all. The frame that results looks like this.

Arguments are at positive offsets from r5, starting at 4, and locals at negative offsets, starting at −8. The compiler's own bookkeeping agrees: blkhed starts the parameter offset at 4 ([[c02.c:572]]), and the count of bytes used below r5 starts at 6 for the three saved registers ([[c02.c:570]]), so the first local lands at −8.

The tst -(sp) in csv is not part of the save area. It reserves one word beyond it. The function then drops the stack pointer by the full size of its locals ([[c11.c:695-702]]), so that there is always exactly one unused word at the top of the stack. This spare word is used for an argument of every call. Arguments are evaluated from right to left, and the first one evaluated, the last in the source, is stored with mov x,(sp) instead of being pushed with mov x,-(sp) and popped afterwards, so there is nothing to pop for it (unless it is a long or floating value, which needs more than one word). A call with one argument cleans up after itself for free, and a call with two needs only tst (sp)+, a two-byte instruction that pops one word. The code that exploits this is comarg ([[c10.c:906-922]]).

Reading it from the top:

  • .globl _main makes the name visible to the linker. C names get a leading underscore so they cannot clash with assembly-language names such as csv.
  • ~~main:, ~i=177770 and ~s=177766 are symbols for the debugger. They record that i lives at −8 and s at −10 relative to r5. Pass c0 writes one for every local ([[c02.c:635-659]]).
  • sub $4,sp makes room for the two locals. Together with the word csv reserved, that leaves the free word at -14(r5).
  • The loop test i<10 became cmp $12,-10(r5) followed by jle L3. The operands are the wrong way round, and the condition is reversed twice: once because the branch is taken when the test fails, and once because the compare has its operands swapped. Chapter 11 explains why the compiler finds it convenient to write it this way.
  • i*i is computed in r1, not r0, because mul needs an odd register to leave a single-word product.
  • The loop's increment, i++, has its own label L4, the target of continue. It is compiled after the body even though it appears before it in the source. Chapter 8 shows how.
  • s, the last argument and so the first evaluated, is passed to printf with mov -12(r5),(sp): that is the free word. Only the format string is pushed, so only one word is popped afterwards.
  • The string itself is placed at the end, in the data segment, as a list of octal bytes. Strings are written to their own temporary file by c0 and copied to the end of the output by c1 ([[c10.c:58-64]]).
