Running the original compiler while reading its source turned up a number of things that are wrong, or strange, or both. They are collected here, with the evidence. None of them should be read as a criticism. This compiler was written by one person, for a machine with 64 kilobytes, and it compiled an operating system that is still studied fifty years later; most of these are in parts of the language that were new at the time and little used. They are interesting because of what they show about how the compiler works.

Each entry says where the behaviour comes from and where the book discusses it. Outputs are from the Sixth Edition system described in the preface.

Bugs

Division by a power of two rounds the wrong way

x / 4 is compiled as an arithmetic shift, ash $-2, which rounds towards minus infinity; division rounds towards zero. So -1/4 is −1 and -7/4 is −2 when the divisor is a constant. With the same divisor in a variable, the answers are 0 and −1. The rewrite is in pow2 ([[c11.c:473-490]]), which does not consider the sign. Chapter 9.

An initialized char array is too short

char s[10] "hi"; reserves only the three bytes of the string. The padding for the rest of the array is written to the string file instead of the main one, because cinit1 sets strflg around it ([[c02.c:176-181]]), so it ends up at the end of the output. Whatever is declared next overlaps the array. Chapter 7.

A small group of bit-fields is overlapped by the next member

After bit-fields totalling eight bits or fewer, the next ordinary member is placed at the same offset as the fields, because align advances by (bitoffs-1)/NBPC, which is 0 for eight bits or fewer, instead of by the number of bytes used ([[c03.c:365-368]]). In decl.c, count lands on top of kind and mark. Chapter 7.

A char bit-field is measured in the wrong unit

The check that a char field fits in the current byte compares with NCPW, characters per word, which is 2, instead of NBPC, bits per character ([[c03.c:387]]). Any char field after the first two bits starts a new byte.

The size of an array member is 2

sizeof applied to a structure member that is an array gives 2, the size of a pointer, because . produces the member's address when the member is an array. The comment in build admits it ([[c01.c:37-41]]). In decl.c, sizeof np->name is 2 although name is char[5]. Chapter 6.

-O breaks computed goto

A label whose address is taken is referenced only by an ordinary operand, which c2 does not count. It deletes the label and the code after the preceding jmp, and the program no longer links. Chapter 13.

A variable that is never assigned

redunbr in c2 uses a register variable p that it never sets, where it means its parameter ap ([[c21.c:495-503]]). It works because both it and its only caller keep their p in r4, and csv saves registers without clearing them. Chapter 13.

A pointer compared with a number

The INIT case of rcexpr tests tree->tr1==CON where it means tree->tr1->op==CON ([[c10.c:203]]), comparing a pointer with the number 21. It does no harm, because c0 writes constant initializers directly and never sends them to c1 as trees.

Limits

Bit-fields cannot be assigned

A field reference is an FSEL node, which is neither a name nor an indirection, so chklval reports “Lvalue required” ([[c01.c:422-430]]), and c1 can only translate FSEL into a shift and a mask, which produce a value ([[c12.c:184-190]]). Fields can be read but never written. Chapter 9.

External longs cannot be initialized

cinit1 treats every four-byte object as a float and expects a floating constant ([[c02.c:212-215]]). long big 5; is “Inconsistent external initialization”. Chapter 7.

The standard compiler has no floating constants

The run script builds /lib/c0 with the floating-point part of the number scanner assembled out ([[run:9-16]]), so plain cc answers every floating constant with “No floating point!”; cc -f uses /lib/fc0, which has it. Chapter 4.

Three register variables, and not one more

A fourth register declaration in a function is an error, “Bad register”, not a request quietly ignored ([[c03.c:280-285]]). Chapter 7.

Fixed tables everywhere

200 symbols, 500 words of expression trees, 200 cases in all the active switches, 100 dimensions and structures, 256 characters in a string, one level of #include ([[c0h.c:13-22]], [[cc.c:383-384]]). Chapter 3.

Seven characters for a member name

Names are significant to eight characters, but a structure member is stored with a . in front of it, so only seven of its own characters count ([[c00.c:289-297]]). Chapter 3.

Curiosities

| and ^ have the same precedence

In opdope both have priority 15 ([[c05.c:65-66]]), so 1 | 2 ^ 3 is (1|2)^3, which is 0. In later C it is 1. Chapter 5.

x=-1

Means x =- 1, with a warning, the only one in the compiler ([[c00.c:235-239]]). Chapter 4.

Computed goto

Labels are treated as static arrays, and goto takes any expression that yields an address, so a label's address can be stored in a variable and jumped to later. It works, without -O. Chapter 8.

A branch that is a comment

A pointer compared with 0 using < can never be less, since pointers compare unsigned. The branch table's entry for “jump if less” in that case is /nop ([[c1t.s:82]]), which the assembler reads as a comment. The code tests the pointer and then does nothing with the result. Chapter 11.

Two ways to call

A call is written jsr pc,*$_f when its first argument went into the free word at the top of the stack, and jsr pc,_f otherwise ([[c1t.s:50-51]]). The two instructions do the same thing. Chapter 11.

Octal nines

The number scanner accepts any decimal digit, so 09 is a legal octal constant whose value is nine ([[c0t.s:133-153]]). Chapter 4.

Constant comparisons are not folded

Neither pass evaluates a relational operator with constant operands, so max(10, 7) produces cmp $7,$12 and a branch, at run time. Chapter 6.

A size that is a pointer

When a structure is used before it is defined, the place in dimtab where its size belongs holds, for a while, a pointer to the structure's tag in the symbol table ([[c03.c:135-138]]), which blkhed later follows and replaces ([[c02.c:590-594]]). Chapter 7.

A null pointer as a table

cregtab, which c1 passes to mean “compile into a register, but do not move things around”, is a table pointer that is never set, and is used only as a distinguishable value ([[c10.c:23]]). Chapter 11.

Self-modifying data

Every switch compiled as a search stores the value being switched on into its own table before searching, as a sentinel. The dispatch code writes to the data it is about to read. Chapter 12.

Arguments laid out like a node

block in both passes builds a tree node by copying its own parameters, which the PDP-11 calling convention leaves in consecutive words on the stack ([[c01.c:387-401]]). Chapter 3.
