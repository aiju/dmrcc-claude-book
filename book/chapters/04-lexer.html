The lexical analyser of c0 is one routine, symbol ([[c00.c:185-318]]), with a few helpers. Each call returns the next token as a small integer. Tokens that carry a value leave it in a global: cval for an integer constant, a keyword number or a string's label, fcval for a floating constant, and csym for the symbol-table entry of a name.

The token numbers are the same numbers used for operators throughout the compiler ([[c0h.c:143-230]]). The + token is 40, and so is the PLUS operator in a tree and in the intermediate file. This lets the parser push tokens straight onto its operator stack.

Looking ahead

C cannot be tokenized without looking ahead one character: + might be followed by another +, and a name ends only when a character that is not part of it has been read. The parser, in turn, sometimes needs to look ahead one token. Both are handled with a single slot of pushback each: peekc holds a character that has been read but not used, and peeksym a token. symbol returns peeksym if there is one ([[c00.c:189-195]]), and otherwise starts from peekc if that is set, and only then reads the input.

Pushing back a token is as simple as assigning to peeksym, and the parser does it constantly. A typical pattern, which appears dozens of times in c02.c and c03.c, is

if ((o=symbol()) != SEMI) {
	peeksym = o;
	...

which tests the next token and puts it back if it is not the one wanted.

peekc is also used by the helpers spnextchar and nextchar ([[c04.c:229-248]] and [[c04.c:218-223]]), which look at the next character without consuming it. The parser uses nextchar in a few places where a character is more informative than a token. For example, a name followed by ( is a function even if it has never been declared ([[c00.c:490-494]]), and a name followed by : at the start of a statement is a label ([[c02.c:428-442]]).

Character classes

The first thing symbol does with a character is look it up in ctab ([[c05.c:159-176]]), which maps each of the 128 ASCII characters to a class. Many classes are tokens in their own right: ; maps to SEMI, ( to LPARN, * to TIMES. For these, symbol just returns the class ([[c00.c:317]]). Others are classes that need further work: LETTER, DIGIT, SPACE, NEWLN, the two quotes, and UNKN for characters that cannot appear in C, such as $ and @. The underscore is a letter. The class numbers of this second group are from 119 up ([[c0h.c:283-293]]), above every operator, so that they cannot be confused with a token.

The character with code 1, the SOH that cc places before each line of an included file, has a class of its own, INSERT. It is skipped like a space, but it sets the flag inhdr so that the next newline does not advance the line count ([[c00.c:207-219]]). Chapter 2 explains why.

Operators

Two-character operators are recognised with subseq ([[c00.c:324-330]]), which takes a character and two tokens. If the next input character is the one given, it is consumed and the second token is returned; otherwise it is left in peekc and the first is returned. So + is handled by

case PLUS:
	return(subseq(c,PLUS,INCBEF));

and - by a nested call ([[c00.c:228-229]]):

return(subseq(c,subseq('>',MINUS,ARROW),DECBEF));

The inner call runs first, since it is an argument of the outer one. If the next character is > it returns ARROW, having consumed the >; otherwise it returns MINUS, and the outer call checks for a second -.

The lexer does not know whether ++ is a prefix or postfix operator, or whether * means multiplication or indirection. It returns INCBEF for every ++ and TIMES for every *, and the parser decides, from whether it has just seen an operand, which one was meant (chapter 5).

Assignment operators

The case for = is the most complicated ([[c00.c:231-245]]):

If = is followed by a blank, it is a plain assignment. Otherwise symbol calls itself to read the following token. If that is one of the binary operators from PLUS to EXOR, the two together form an assignment operator such as =+, and since the assignment operators are numbered in the same order ([[c0h.c:207-217]]), its number is found by adding a constant. If it is another =, the pair is ==. Otherwise the token is pushed back and the = stands alone.

Reading a whole token after the =, rather than a character, has a pleasant consequence: =<< and =>> need no special code, because << and >> come back as single tokens.

It also makes the famous ambiguity concrete. x=-1 is read as x =- 1, which subtracts one from x. If you meant x = -1 you had to write a space after the =. The compiler cannot know which was intended, so when the operator is -, & or * (all of which also have a unary meaning) and it is followed immediately by something other than a blank, it assumes the assignment operator and warns ([[c00.c:235-239]]). This is the only warning in the compiler. It is implemented as an error that then decrements the error count.

Names and keywords

A letter starts a name ([[c00.c:288-303]]). Characters are collected into symbuf up to eight of them, and any more are read and ignored. The buffer is padded with zero bytes, so that names can be compared eight bytes at a time, and lookup is called. If the name is a keyword lookup returns KEYW with the keyword's number in cval; otherwise it returns NAME with the entry in csym. sizeof is looked up as a keyword but returned as an operator token, SIZEOF, since that is how the expression parser treats it.

If mosflg is set, a . is put in front of the name, putting it in the name space of structure members. The parser sets the flag when it reads . or -> ([[c00.c:589-592]]) and while it reads the declarations inside a structure.

Strings and characters

A double quote starts a string, which getstr ([[c00.c:336-354]]) reads into savstr. Each string is given a new label number from isn, the compiler's counter for generated labels, and that number is the value of the token. The characters themselves are not written out until the parser decides what to do with the string: in an expression it becomes a static array of char at that label, written to the string file by putstr ([[c00.c:361-374]]); as the initializer of a char array it is written in place. nchstr counts the characters including the terminating null, so that the initializer code knows how many bytes it has.

Character constants are read by getcc ([[c00.c:381-395]]), which stores the characters directly into the bytes of the integer cval, through a char pointer. Up to two are allowed, so 'ab' is a legal constant whose value has a in the low byte and b in the high one. As the comment says, this depends on the layout of characters in a word.

Both use mapch ([[c00.c:402-459]]) to read a character and interpret escapes. The escapes are \n, \t, \b, \r and up to three octal digits. Any other character after a backslash stands for itself, which is how \\, \' and \" work. A backslash before a newline continues the string on the next line. The octal case reads one character too many and has to keep it; since peekc may already be in use, mapch has a private pushback of its own, the static variable mpeek.

Numbers, in assembly language

A digit, or a ., sends symbol to getnum ([[c00.c:275-280]]), with base 8 if the first digit is zero and 10 otherwise. getnum is not in C. It is in c0t.s, written in assembly language, because it uses the floating-point unit directly to accumulate the value of a floating constant.

It reads digits, accumulating the integer value in _cval with a mul instruction ([[c0t.s:133-153]]) and, in parallel, the floating value in fr0. The digit routine accepts any decimal digit, so 09 is a legal octal constant with the value nine. A . or an e marks the number as floating, and the floating value is then scaled by the right power of ten ([[c0t.s:84-107]]).

The return value is a token. A plain integer returns CON ([[c0t.s:87]]). If there were no digits at all, the . was not part of a number, and getnum returns 39, the number of the . operator ([[c0t.s:78-80]]). That is how s.x is recognised: the dot goes to getnum because it might start .5, and comes back as an operator.

A floating constant returns one of two tokens. If only the first of its four words is non-zero, it is a SFCON, a “short” floating constant, and its first word is put in cval ([[c0t.s:108-122]]). The PDP-11's floating-point instructions can take an immediate operand, but only one word of it, the high word, which holds the sign, the exponent and the top seven bits of the fraction. So constants such as 1.0, 2.5 or 0.75, which need no more than eight significant bits, can be written into the instruction. Anything else is a FCON, and the parser immediately writes its four words to the data segment under a new label ([[c00.c:506-509]]). In the listing of fl.c below, 2.5 becomes the immediate $40440.

All of this is between .if fpp and .endif. The other branch, .if 1-fpp ([[c0t.s:124-131]]), replaces the whole floating part with the message “No floating point!” and returns CON. Which branch is assembled depends on the symbol fpp ([[c0t.s:8]]), and the script that builds the compiler, run, edits it ([[run:9-25]]). It sets fpp to 0 and builds /lib/c0, then sets it to 1 and builds /lib/fc0 with cc -f, which links in a program that simulates the floating-point unit when the hardware is absent. The standard first pass therefore never reaches a floating-point instruction and runs on any PDP-11, while the one that understands floating constants is used only with cc -f.

On the distribution tape used for this book the result is exactly what the script says. The plain compiler rejects every floating constant:
