Chapter 12

The Switch Statement

  1. A jump table
  2. A linear search
  3. A hash table
  4. Try it

Of all the statements, switch is the only one whose code is not a simple arrangement of branches. c0 compiles the body with the case labels in it, puts the controlling value in r0, and hands c1 a SWIT record listing the values, their labels, and the default (chapter 8). getree reads the list into the now unused tree space and calls pswitch (6524–6533).

pswitch (6141–6225) is under a hundred lines, and contains three different dispatch methods, each worth a look. It first sorts the cases with a bubble sort, which is also where duplicate values are found and reported (6227–6256). Then it chooses.

A jump table

If the values are dense, meaning the range from the smallest to the largest is no more than three times the number of cases, pswitch builds a table with one entry for every value in the range (6160–6174). The code, from the string dirsw (6107–6114), subtracts the smallest value, compares with the range, and jumps through the table:

sub	$1,r0
cmp	r0,$3
jhi	L2
asl	r0
jmp	*L10001(r0)
.data
L10001:L4
L5
L2
L6
.text

This is dense() from sw.c, with cases 1, 2 and 4. Values in the range that have no case, here 3, get the default label in the table. The comparison uses jhi, the unsigned branch, which catches values below the smallest case as well as above the largest: after the subtraction they are negative, and a negative number compared unsigned is very large. One comparison checks both bounds.

A linear search

If the values are spread out and there are fewer than eight of them, pswitch searches a list (6175–6188):

mov	$L10003,r1
mov	r0,L10004
L10005:cmp	r0,(r1)+
jne	L10005
jmp	*L10004-L10003(r1)
.data
L10003:1
144
1750
L10004:..
L10
L11
L12
L8
.text

The list of values, 1, 100 and 1000, is followed by a spare word, and before searching, the code stores the value being looked for in that word. So the search is certain to find it, and the loop needs only one comparison per step, with no test for the end of the list. This is the sentinel technique, and the word is overwritten each time the switch is executed; the .. the compiler writes into it is just a placeholder.

When the loop stops, r1 points just past the matching value. The labels are laid out in a second list, at a fixed distance from the first, so jmp *L10004-L10003(r1), which adds that distance to r1, fetches the label that corresponds to the value found. The label after the last case label, matching the sentinel, is the default.

A hash table

With eight or more widely spread values, pswitch builds a hash table (6189–6222). The hash function is the remainder on division by the number of buckets. To choose that number, pswitch tries every value between a quarter and a half of the number of cases, and keeps the one that minimizes the number of buckets multiplied by the size of the largest bucket, a rough measure of table size and search time together (6190–6204).

The code, from hashsw (6126–6139), for many() in sw.c, with ten cases and two buckets:

mov	r0,r1
clr	r0
div	$2,r0
asl	r1
add	$L10008,r1
mov	r0,*(r1)+
mov	(r1)+,r1
L10007:cmp	r0,-(r1)
jne	L10007
jmp	*L10011-L10009(r1)

The value is divided by the number of buckets, leaving the quotient in r0 and the remainder in r1. The remainder, doubled, indexes a directory of bucket addresses, L10008. Each bucket begins with a spare word, and the quotient is stored into it through the directory entry, which is the sentinel trick again. Then r1 is set to the start of the next bucket, which is the end of this one, and the bucket is searched backwards with autodecrement until the quotient is found. Finally the label is fetched from a parallel table, as in the linear search.

The buckets hold quotients, not values. Within a bucket every value has the same remainder, so the quotient alone identifies it, and the comparison can use the number already in r0. The data for many() is

L10010                  / bucket 1,
L10011                  / end of the last bucket

The directory has one more entry than there are buckets, so that the end of the last bucket can be found the same way as the others; conveniently it is also the start of the label table.
