Declarations are handled by c03.c, with external data and its initializers in c02.c. The work divides into three parts: reading the keywords that begin a declaration, reading each declarator to find the name and its type, and then allocating storage for the name according to its storage class.

The keywords

declist (3365–3377) reads a sequence of declarations. It is called at the start of every function body with storage class 0, for the parameter declarations with ARG, and inside a structure with MOS, “member of structure”. It returns the total size of what it declared, which is only interesting for a structure.

Each declaration begins with keywords, read by getkeywords (3382–3446). A storage class keyword replaces the default, and conflicting ones are an error. A type keyword sets the type, and a second one is a “Type clash”. long is not a type but a modifier, counted in longf, which turns int into long and float into double (3432–3439). So long float is a legal way of writing double.

When a token arrives that is not a keyword, getkeywords decides whether it has seen a declaration at all. If no keyword was read, it returns −1 and declist stops: this is how the end of the declarations at the head of a function is found, since a statement does not start with a keyword that names a type or class. Otherwise missing parts get defaults, int for the type and AUTO for the class, so register x; declares an integer and int x; inside a function declares an automatic.

Reading a declarator

A C declarator reads from the inside out: in char *argv[5], argv is first an array, because [] binds more tightly than *, and then the elements are pointers, and the pointers point to char. getype (3642–3699) parses this with a very small recursive routine:

A * calls getype recursively for the rest of the declarator, then shifts the result left and puts PTR in the lowest field. A ( reads a nested declarator. A name records itself in defsym and starts from type 0. After the name or the parentheses, each () or [] that follows shifts the type left and puts FUNC or ARRAY in the lowest field.

The type getype returns has its modifiers in the order they were attached, with the last one in the lowest field. For *argv[5] the array is attached first, when the name is read, and the pointer last, when the recursion unwinds, so the word has PTR in the lowest field and ARRAY above it. That is the wrong way round: the type word wants the outermost modifier, the one applied to the name first, at the bottom. So decl1 reverses the fields before adding the base type (3562–3566):

type = 0;
do
	type = type<<TYLEN | (t1 & XTYPE);
while (((t1=>>TYLEN) & XTYPE)!=0);
type =| tkw;

Array bounds are read with conexp and stored in dimtab. The first bound of an array is stored at the index recorded in the name's ssp, and each later bound multiplies the ones before it (3678–3691). So int m[3][4] leaves 12 and 4 in dimtab: the first entry is the total number of elements, which is what length wants, and the second is the number of elements in each row, which is what subscripting m once leaves you with. Taking a subscript moves the node's ssp forward by one (chapter 6). A missing bound is recorded as 1.

When a function is declared at the outer level, the parentheses may hold its parameter names. The global xdflg is set only while an external definition's declarator is being read, and in that case getype calls declare to read the names as declarations of class ARG1 (3665–3672).

After a parenthesised declarator, the loop that multiplies earlier bounds uses the local ds, which that invocation of getype never set, so the bound [4] is simply recorded. For these declarations that happens to be the right answer.

Allocating storage

decl1 (3539–3637) handles one declarator. After getype and the reversal, it checks that the name is not already declared in a conflicting way, sets its class and type, and then allocates it according to its class (3617–3634):

  • A function is always external, even if declared inside another function.
  • An automatic gets the next slot below the frame pointer. autolen is the number of bytes used so far, starting at 6 for the saved registers, and the variable's offset is its negation, so the first int is at −8.
  • A static gets a new label, and its storage is allocated at once: decl1 writes .bss, the label, space for the object and .text into the middle of the function's code. You can see the result in init.s below, where calls becomes L4 and is allocated right after ~~main:.
  • A register variable gets the next register down from r4. Only int, char and pointers are allowed, and only three of them. A fourth is not quietly demoted to an automatic, as later compilers did; it is an error, and the message prints the type in octal:

regs.c

f()
{
        register a, b, c, d;

        a = b = c = d = 0;
}

cc -c regs.c

3: Bad register 0

Parameters are handled in two stages, because in this C their types come after their names: f(a, b) char *b; { ... }. As getype reads the names in the parentheses, decl1 links them into a list, in order, using the hoffset field of each symbol as the link (3580–3586). Then the declarations between ) and { are read with class ARG, which sets their types. Finally blkhed (3214–3254) walks the list and assigns offsets 4, 6, 8 and so on in the order the names appeared. On the way, float parameters become double, since that is what callers pass, and array parameters become pointers. A parameter that is never declared stays an int, and a declared name that is not in the list draws “Not an argument”.

Structures

struct is read by strdec (3452–3506), called from getkeywords. A tag is entered in the symbol table with class STRTAG and given a slot in dimtab for the structure's size. If a body in braces follows, its members are read with declist(MOS), which returns the size, and the size is stored in the tag's slot. The members' names are read with the . prefix of chapter 3.

Because all members share one name space, a member name can belong to only one offset and one type. decl1 allows a member to be declared again only if the new declaration agrees in both (3568–3576, 3613–3614); otherwise it is “redeclared”. Kernel programmers worked around this by giving each structure's members a distinct prefix.

A structure can be mentioned before it is defined, as long as only pointers to it are declared: struct node *head; before struct node { ... }. Then the size is not yet known, and strdec returns the type RSTRUCT and, in place of a size, a pointer to the tag's symbol table entry (3484–3487). decl1 stores that pointer in dimtab as though it were a size. At the start of the next function, and after each external declaration of a structure, blkhed goes through the symbol table, follows each such pointer to the tag, and replaces it with the tag's real size slot (3239–3243), by which time the structure has usually been defined.

Alignment and bit-fields

align (3705–3744) is called for every member of a structure with the current offset and returns how many bytes of padding are needed before the member. Everything except char is aligned to an even address. Bit-fields are packed into words: bitoffs is the number of bits used in the current word, and a field that does not fit in what is left starts a new word.

When an ordinary member follows some bit-fields, align must step past the bytes the fields occupy. It does so with this line (3714–3717):

if (flen==0 && bitoffs) {
	a =+ (bitoffs-1) / NBPC;
	bitoffs = 0;
}

(bitoffs-1)/NBPC is the index of the byte holding the last bit used, not the number of bytes used. For fields totalling more than eight bits it is 1, and the alignment that follows rounds the offset up to the next word, which happens to be right. For fields totalling eight bits or fewer it is 0, the offset does not move, and the following member is placed on top of the fields. The compiler really does this. In decl.c from chapter 6, kind:3 and mark:1 are followed by int count, and the program reports that count is two words from the start, at byte 4, which is where the fields are. The structure is two bytes smaller than it should be.

There is a second, smaller slip a few lines further on: for a char field, the check that it fits compares with NCPW, the number of characters per word, instead of NBPC, the number of bits per character (3736). And as chapter 6 showed, fields cannot be assigned to at all. Bit-fields were evidently new, and not much used.

External definitions and initializers

At the outer level, extdef (2661–2706) reads the keywords, with EXTERN as the default class, and then each declarator. A function whose declarator is followed by { or by a keyword is a function definition, handed to cfunc (next chapter). Anything else is data, handed to cinit (2731–2804).

Data without an initializer is written out as a common block, .comm _x,size (2757–2760), which the loader merges with any other definitions of the same name. This is why the Sixth Edition, like most Unix C compilers after it, allowed a global to be defined in more than one file.

An initializer has no =. It is either a single expression or a list in braces, each item read by cinit1 (2811–2879), which checks it against the width of the element: a byte, a word, or four or eight bytes of floating point. A word can be initialized with an integer constant, written directly, or with an address, which is written as an expression tree with the special operator INIT for the second pass to print (2846–2859). That is how char *msg "hello" becomes the word L2, the label of the string.

An array without a bound takes its size from the number of initializers; this is done by patching the bound in dimtab after the list has been read (2790–2796). A structure is initialized, as the comment says, by pretending it is an array of integers (2749–2756), which works as long as every member is a word. A string in the wrong place

Now look at s, declared as char s[10] "hi". The three bytes of the string are written where they belong. The remaining seven bytes of the array should follow them, but the .=.+7 that reserves them is at the very end of the file, among the string constants. The code responsible is in cinit1:

c02.c
 2820          if ((peeksym=symbol())==STRING && type==CHAR) {
 2821                  peeksym = -1;
 2822                  if (ninit)
 2823                          bxdec();
 2824                  putstr(0);
 2825                  if (nel>nchstr) {
 2826                          strflg++;

 2828                          strflg = 0;

 2830                  }

putstr(0) writes the string into the main output file. Then the padding is written with strflg set, which sends it to the string file instead, and that is copied onto the end of the output by c1. So the array really occupies three bytes, rounded up to four by the assembler, and whatever is declared next begins inside it. The effect is easy to demonstrate:

strinit.c

char s[10] "hi";
char *msg "hello";
int after 1234;

main()
{
        printf("s at %o, msg at %o, after at %o\n", s, &msg, &after);
        s[4] = 'X';
        printf("%s %d\n", msg, after);
}

a.out

s at 1230, msg at 1234, after at 1236
@ 1234

msg begins four bytes after s, and storing into s[4] overwrites the low byte of the pointer msg, so printf prints garbage instead of “hello”.

The fix is simply to leave strflg alone here. Initialized char arrays larger than their initializer were evidently rare in 1975.

Longs

One more gap: cinit1 treats every four-byte object as a float (2861–2864). It expects a floating constant, and anything else is “Inconsistent external initialization”. long was the newest type in the language, and there is no way to initialize an external long:

long big 5;
