Part two

Commentary

  1. Preface

    Why this compiler is worth reading, what C looked like in 1975, and how the book is arranged.

  2. 1The Shape of the Thing

    What happens when you type cc, why the compiler is split into passes, and just enough PDP-11 to read its output.

  3. 2The Driver and the Preprocessor

    How cc runs the passes and cleans up after them, and the small preprocessor hidden inside it.

  4. 3The World of c0

    The first pass's main loop, its symbol table, its tree nodes, and the intermediate file it writes for the second pass.

  5. 4Lexical Analysis

    How symbol() turns characters into tokens, why x=-1 draws a warning, and the number scanner written in assembly language.

  6. 5Parsing Expressions

    The operator-precedence parser tree(), its three stacks, and the table of priorities that decides where every operator binds.

  7. 6Types and Conversions

    How a C type fits in sixteen bits, and how build() checks every operator and inserts conversions, scaling and rewrites as the tree is made.

  8. 7Declarations

    Reading declarators inside out, laying out structures and bit-fields, allocating storage, and initializing external data; with three bugs found by running the compiler.

  9. 8Functions and Statements

    How c0 lays out each kind of statement as labels, jumps and conditional branches, including the trick that moves a for loop's increment after its body.

  10. 9Rewriting Trees

    How c1 reads the trees back, and how optim() folds, reorders and reshapes them for the PDP-11 before any code is generated.

  11. 10The Code Tables

    The four tables of code templates in table.s, the little language they are written in, and how match() picks one for each node.

  12. 11Generating Code

    rcexpr and cexpr: the special cases, the expansion of templates, the choice of registers, function calls, and the compilation of conditions into branches.

  13. 12The Switch Statement

    The three ways c1 dispatches a switch: a jump table, a linear search with a sentinel, and a small hash table whose buckets hold quotients.

  14. 13The Object Code Improver

    c2 reads the assembly language back in and rewrites it: jumps to jumps, dead code, merged tails, inverted loops, registers remembered, and a trick borrowed from BLISS-11.

  15. 14One Program, Start to Finish

    A small program followed through every stage of the compiler, with the real intermediate file, trees, templates and code at each step.

  16. AppendixBugs, Limits and Curiosities

    Everything odd found while writing this book, each checked against the real compiler: eight bugs, several limits, and a few things that are simply surprising.
