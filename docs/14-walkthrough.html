Chapter 14

One Program, Start to Finish

This chapter follows one program through the whole compiler, pass by pass, using what the compiler really produced at each step. It pulls together the previous chapters, and can also be read first, as a tour, with the links used to find the details.

The program counts the vowels in a string:

/* Count the vowels in a string. */

char *s "hello, world";

main()
{
        register char *p;
        int n;

        n = 0;
        for (p = s; *p; p++)
                switch (*p) {
                case 'a': case 'e': case 'i':
                case 'o': case 'u':
                        n++;
                }
        printf("%d\n", n);
}

It uses an external variable with an initializer, a register variable, a for loop, a switch with several cases sharing one action, and a call. Here is the whole session on the simulated PDP-11, compiled without and then with -O:

“hello, world” has three vowels, so the answer is right. The rest of the chapter explains how it was reached.

cc

cc sees one argument ending in .c (201–213), creates its temporary files, and calls expand. The file begins with /, not #, so there is nothing to preprocess, and c0 is given vowels.c itself (348–351). Then c1, c2 if asked for, as, and, since -c was not given, ld with crt0.o and the C library.

c0

c0's main loop calls extdef for each external definition (chapter 3). The first token is the comment, which symbol skips (chapter 4), and then the keyword char.

The external

extdef reads the keywords with getkeywords and the declarator *s with decl1 and getype, giving s the type pointer to char, 011 octal (chapter 7). Its class is EXTERN, and because it is being defined at the outer level it gets the flag FNDEL, so it will survive the end of the next function. extdef writes SYMDEF, which will become .globl _s. The declarator is not a function, so cinit handles the initializer. The next token is a string, but the object is a pointer, not an array of char, so the string is an ordinary expression: tree turns it into the address of a static array labelled L1, whose bytes go to the string file, and cinit1 writes the address as an INIT tree (chapter 7).

main

The next external definition is main(). getype sees the parentheses and makes it a function, and extdef calls cfunc (chapter 8), which writes PROG and RLABEL and allocates L2 for the exit. The body's declarations are read by blkhed. register char *p takes r4, and regvar drops to 4. int n is automatic: autolen goes from 6 to 8, so n is at −8. blkhed writes debugger records for both, then SETREG 4, and returns 8, which becomes SAVE 8.

Then the statements:

  • n = 0; is an expression statement: tree builds = with n and 0 (chapter 5), and rcexpr writes it out with an EXPR record.
  • The for writes its initialization p = s, the label L3 for the test, and the test *p as a CBRANCH to L4 if false. The increment p++ is parsed and kept in memory, with treespace moved above it, and L5 is allocated for it (chapter 8).
  • The body is the switch. *p is written inside an RFORCE, a jump to L7 is written where the dispatch code will go, and the body is compiled. Each case reads its constant with conexp, allocates a label, L8 to L12, and records the value and label in swtab. n++ is written, carrying the constant 1 as its increment. After the body, pswitch writes a jump to L6, the end of the switch; the label L7; and the SWIT record with the default L6 and the five pairs.
  • Back in forstmt, the label L5 and the saved increment are written, then a jump back to the test, and the exit label L4.
  • The call to printf is one tree: CALL with the function name and a , joining the address of the format string, L13, and n.

c1

c1 reads the file with getree (chapter 9). The first records print .globl _s, .data and _s: directly. The INIT tree prints the address, L1. PROG, RLABEL and the debugger records become .text, _main:, ~~main:, ~n=177770 and ~p=r4. SETREG 4 sets nreg to 3, leaving r0 to r3 for expressions, and SAVE 8 becomes jsr r5,csv and tst -(sp): two bytes beyond the save area are needed for n, and that is exactly the word csv already reserved, so one more word is pushed as the free word at the top of the stack (chapter 1).

Some things to notice:

  • n = 0 matches the first pattern of = in efftab, %a,z, and becomes clr -10(r5).
  • The test *p reaches c1 as *r4, which optim turns into the name 0(r4), printed (r4). It is compiled with cctab, where comparing with zero is a tst, and since the operand is a char, tstb. cbranch adds jeq L4.
  • The RFORCE of *p loads the character into r0 with movb, which extends its sign.
  • n++, for its effect only, becomes inc -10(r5), and p++ becomes inc r4.
  • The SWIT record goes to pswitch (chapter 12). The five values 97 to 117 span a range of 20, more than three times five, so a linear search is generated, with the value stored as a sentinel after the list.
  • For printf, n is the first argument pushed, and the stack is empty, so it goes into the free word with mov -10(r5),(sp); only the format's address is really pushed, and only one word is popped.

c2

With -O, c1's output goes through c2 (chapter 13). movedat moves the switch table to the front. Then refcount finds that the five consecutive case labels L8 to L12 are one place, and makes every reference use the last one, L12. Jumps to jumps disappear: the end of the switch, L6, is the same place as the increment L5. codemove moves the dispatch code, which was reachable only by a jump, to where it is jumped from, inside the loop, and the loop is inverted so that the test is at the bottom:

The loop is now: test the character, and if it is not zero, search the vowel list, add one to n if the search finds a vowel, and step the pointer. The object file has 62 bytes of code, as size reported.

as, ld, and the answer

The assembler turns each jbr and jne into a short branch if its target is close enough, as all of these are, and leaves the undefined names _printf, csv and cret as external references, as nm shows. The symbols beginning with ~ are there for the debugger, with the class of each local visible in nm's output: n at 177770, an offset, and p at 4, a register. ld puts crt0.o in front, which sets up the arguments and calls _main, and pulls in printf, csv and cret from the library. The finished program is 1298 bytes, and it prints 3.
