Chapter 2

The Driver and the Preprocessor

  1. Running the passes
  2. The preprocessor

The file cc.c contains two programs that have little to do with each other. The first, main and its helpers, is the command that runs the compiler passes, the assembler and the loader in turn. The second, starting at expand, is the C preprocessor. There is no separate cpp in the Sixth Edition; cc preprocesses a file itself, and only if it has to.

Running the passes

main (149–318) first walks the argument list. Options are recognised by their second character (157–200):

OptionEffect
-ccompile to .o files but do not link
-Sstop after c1 (or c2) and keep the assembly language in a .s file
-Orun the optimizer c2
-Ponly preprocess, leaving the result in a .i file
-pcompile for profiling: c0 is told to count calls, and a different start-up file is linked
-fuse the floating-point versions of the passes and link the floating-point simulator
-2link with an alternative start-up file and library
-t0, -t1, -t2take that pass from /usr/c instead of /lib: a way to try a new version of the compiler before installing it

Any other option, and every argument not starting with -, is passed on towards the loader. An argument whose name ends in .c is also added to the list of files to compile, and its .o is what the loader will see (201–213). getsuf (683–701) finds the suffix, and refuses names whose last component is longer than 14 characters, the limit on a Sixth Edition directory entry. nodup keeps an object file from being given to the loader twice, which would otherwise happen with cc x.c x.o.

Next come the temporary files (217–234). cc starts from the name /tmp/ctm0a and increments its last letter until it finds a name that does not exist, then creates that file with mode 0400 so that no other cc running at the same time will choose it. The other temporaries are derived by replacing the 0: ctm1a and ctm2a for c0's output, ctm3a for the assembly language, ctm4a for the preprocessed source and ctm5a for c1's output when c2 will follow.

The interrupt signal is caught so that the temporaries can be removed if the user types the interrupt character, but only if interrupts were not already being ignored (226–227). signal returns the previous setting; if its low bit is set the previous action was “ignore”, which is what a command run in the background with & inherits. Catching the signal in that case would let an interrupt typed at the terminal kill a background compilation, so cc leaves it alone. This idiom appears throughout Sixth Edition commands.

Then each .c file is compiled in turn (235–296). The steps are exactly the ones in the diagram in chapter 1: expand, then c0 with the source and two temporaries, then c1, optionally c2, and then as. The assembler is given the flag -, which makes every undefined symbol external, so that the compiler never needs to emit .globl for the functions and variables a file uses but does not define. The assembler always writes its output to a.out, so cc renames that to the .o file by linking and unlinking (290–295), since there was no rename system call.

If any pass fails, cflag is set so that loading is skipped, and the loop goes on to the next file. Finally, if everything compiled, the loader is run with the start-up file first, then the objects, then the C library -lc and the assembler library -l (298–316). When a single source file was compiled and linked, its .o is removed again, since the user presumably wanted only a.out.

callsys (716–736) runs one program. It is a textbook fork, exec and wait. The low byte of the status returned by wait is the number of the signal that killed the child, if any. For an interrupt it quietly cleans up; for any other signal except 14, which it ignores for a reason the source does not record, it reports a “Fatal error” in that pass, which in practice meant that the compiler had run out of memory or had a bug. Otherwise it returns the child's exit status, and each pass exits with a non-zero status if it reported any errors (1448).

The preprocessor

The preprocessor is invoked by expand (334–389). It opens the source file and reads its first character. If that is not #, the file needs no preprocessing and expand returns the file's own name, so c0 reads the original. This is why most source files of the compiler start with a line holding only #: without it, the #include lines would reach c0, which would reject them.

If the first character is #, it must be put back. There is no ungetc for the buffered I/O of the period, so expand reaches into the buffer itself (352–353). A buffer is an array of 259 integers: a file descriptor, a count of characters left, a pointer to the next character, and the characters. Incrementing the count and decrementing the pointer un-reads the character.

Then a symbol table of 200 entries is cleared and the directive names are entered into it (360–365). Directives are looked up in the same table as macros, which saves a separate keyword table: after #, the next word is looked up and the pointer returned is compared with the pointers remembered here. The last entry, unix, is not a directive. It is a predefined macro whose value is its own name, so that programs can test for Unix with #ifdef unix.

The main loop copies the file line by line into the temporary, using getline to read and process each line (375–382). Two details in this loop matter to c0.

First, every input line produces exactly one newline in the output, even when the line is a directive or is skipped by a conditional. Comments are removed, but the newlines inside them are written out too (565–569). So the lines of the preprocessed text correspond one for one with the lines of the source, and c0's line numbers in error messages are right.

Second, lines that come from an included file are preceded by the character with code 1, ASCII SOH (376–377). c0 treats this character as white space, but it also sets a flag, inhdr, that stops the next newline from being counted (1556–1568, 4028–4047). The lines of a header therefore do not advance the line count, and errors in the main file are reported at their true line numbers. Errors in the header itself are reported at the line of the #include, which is as good as one could do without passing file names. With -P the markers are left out, since the output is meant for people.

Reading a line

getline (391–498) is a small state machine. state is 0 in an ordinary line and 1 after a # at the start of a line. The word following # moves it to 2 for define, 3 for include, 4 for ifndef and 5 for ifdef (431–453). The line is scanned character by character and copied into a line buffer, except that identifiers and quoted strings are recognised as units.

An identifier in an ordinary line is looked up with lookup(namep, 0). If it names a macro, lookup calls subst, which removes the name from the line buffer and pushes the macro's value back onto the input, so it will be read again and any macros inside it will be expanded in turn (649–681). The pushback is a stack, pushbuff, read by getc1 before the file. Because it is a stack, subst first copies the replacement into revbuff and then pushes it back from the end, so it comes out in the right order. A space is added on each side of every replacement, which is why the expanded text below is so airy. Rescanning also means a macro could expand forever; subst gives up after a depth of 100, and it treats a macro whose value is its own name, like unix, specially, copying the name without rescanning it.

After #ifdef or #ifndef, the name is looked up with enterf set to −1, which neither enters it nor expands it, and the result is combined with the state in one expression (416):

cc.c
  415                          if (state>3) {
  416                                  if (flslvl==0 &&(state+!lookup(namep,-1)->name[0])==5)
  417                                          trulvl++;
  418                                  else
  419                                          flslvl++;

A found name gives !name[0] equal to 0 and a missing one gives 1. So the sum is 5 for #ifdef of a defined name (5 + 0) and for #ifndef of an undefined one (4 + 1), which are exactly the cases where the following lines are wanted. Nesting is handled by two counters: trulvl counts conditionals that were true, flslvl those that were false or are inside a false one, and a line is copied only when flslvl is zero. #endif decrements whichever counter is non-zero, preferring flslvl. There is no #else and no #if.

For #define, the name after the directive is entered into the table, and the rest of the line is stored as its value in a 2000-byte string area (454–463). For #include, the quoted file name is opened on the second buffer, ibuf2, and reading continues from it (477–489). With only two buffers there can only be one level of inclusion, and a nested #include is an error. When the included file ends, getc1 closes it and switches back (590–596).

Macros with arguments

A #define whose name is followed immediately by ( stores a value that begins with (: the parameter list and the body together. When subst sees such a value it calls expdef (776–820), which splits the parameter names out of the stored text with token, reads the actual arguments from the input with coptok, counting parentheses and skipping over quoted strings, and then copies the body with each parameter name replaced by its argument.

These last routines look different from the rest of the file: they are indented with spaces instead of tabs, braces are placed differently, and declarations are written differently. The facility was evidently added by another hand. It is a reminder that the Sixth Edition was a working system that many people changed, not a finished product.

An example

Here is a file that uses most of these features, the header it includes, and the output of cc -P, shown with od -c so the newlines are visible.

pp2.c

#include "defs.h"
#define max(a,b) ((a)>(b)?(a):(b))
#define twice(x) (2*(x))
/* a comment
   spanning lines */
#ifndef SIZE
int unused;
#endif
f(n) { return(max(twice(n), SIZE)); }
g() { return(undef+); }

defs.h

#define SIZE 100
int table[SIZE];

od -c pp2.i

The first newline comes from the #include line and the second from the #define in the header. Then the header's second line appears with SIZE replaced, followed by nine more newlines: the one ending that line, the one getc1 writes when the header runs out, the two #defines, the two lines of the comment, the #ifndef, the skipped declaration and the #endif. SIZE is defined, so int unused; is dropped, and the nested macro call max(twice(n), SIZE) is fully expanded.

In this output f is on line 12, three lines later than in the source, because the header's lines are included. In the version that cc gives to c0, the first three newlines are each preceded by an SOH and are not counted, so c0 sees f on line 9, as in the source. The last line contains an error, and compiling the file with cc -c reports it on line 10, where it really is:

10: Expression syntax
10: undef undefined

That second message, from blkend (3261–3277), shows that c0 treats an undefined name used in an expression as a label that was never defined. Chapter 5 explains why.
