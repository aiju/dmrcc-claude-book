The third pass runs only with cc -O. Its comments call it the object code improver, which is more modest and more accurate than “optimizer”: it knows nothing of C and nothing of the trees that produced the code. It reads the assembly language that c1 wrote, as text, and improves it with transformations that are each simple and local, repeated until nothing changes. Its source is c20.c and c21.c, about thirteen hundred lines.

c2 is the kind of pass now called a peephole optimizer, and much of what it does is repair. c0 and c1 generate code one statement at a time without looking back, and they leave behind jumps to the next instruction, jumps to jumps, and labels nobody uses. It is simpler to let them do that and clean up afterwards than to make every part of the compiler avoid it.

Reading code as a list

Each line of input becomes a struct node (9414–9423) in a doubly linked list:

c2h.c
 9414  struct node {
 9415          char    op;
 9416          char    subop;
 9417          struct  node    *forw;
 9418          struct  node    *back;
 9419          struct  node    *ref;
 9420          int     labno;
 9421          char    *code;
 9422          int     refc;
 9423  };

op is the instruction, recognised by oplook (9872–9909) with a small hash table of opcode names, and subop is the condition of a conditional jump, or BYTE for the byte form of an instruction. A label that is a number, L followed by digits, is stored as that number, so labels can be compared with integers; jumps to such labels have the number in labno, and after refcount has run, a pointer to the label's node in ref. Anything else, operands included, is kept as a string in code. Lines the table does not know, such as the values in a switch table or the debugger's symbols, have op 0 and are carried through unchanged. The labels in a switch table are recognised as a kind of their own, JSW, so that they count as references (9899–9905).

The input is processed one function at a time. input (9646–9701) stops at each .globl, which c1 writes before every function, and main (9564–9644) then improves and prints that piece before reading the next. So memory need only hold one function, and memory for nodes is taken from the system with sbrk in 2000-byte chunks (10445–10463). When c2 finishes it can print how much memory it used; every example in this book fitted in 14K.

The main loop is:

c20.c
 9600          do {
 9601                  isend = input();
 9602                  movedat();
 9603                  niter = 0;
 9604                  do {
 9605                          refcount();
 9606                          do {
 9607                                  iterate();
 9608                                  clearreg();
 9609                                  niter++;
 9610                          } while (nchange);
 9611                          comjump();
 9612                          rmove();
 9613                  } while (nchange || jumpsw());
 9614                  addsob();
 9615                  output();
 9616                  if (niter > maxiter)
 9617                          maxiter = niter;
 9618                  lasta = firstr;
 9619          } while (isend);
 9620          flush();

movedat first moves every .data section to the front of the function, so that the code is one uninterrupted list (10646–10692). Then the inner loops run the transformations below until an iteration makes no change.

Jumps

refcount (9911–9948) finds each jump's label and counts the references to every label. A jump to one of several consecutive labels is redirected to the last of them, the one immediately before the next instruction. A label with no references is deleted, which is where most of the “redundant labels” in the statistics come from.

iterate (9950–10010) then makes a pass over the list:

  • A jump to an unconditional jump is redirected to the final destination.
  • A conditional jump over an unconditional one, jeq L1; jbr L2; L1:, becomes a single reversed jump, jne L2, using the table revbr (9561).
  • After an unconditional jump, everything up to the next label is unreachable and is deleted.
  • A jump to the label immediately following it is deleted. Since every return jumps to the function's single exit, this removes the jbr L1; L1: at the end of most functions.
  • xjump (10012–10035) looks at the instructions before a jump and before its target. If they are identical, the jump can be moved back one instruction, and the duplicate deleted. Repeated, this merges the identical tails of two paths. This is called cross-jumping.
  • codemove (10065–10136) moves blocks of code. If a jump goes to a block that is itself only reachable by jumping, the block is moved to the jump, saving the jump. Its second part, at ivloop, inverts loops: a loop with its test at the top and a jump back at the bottom, as c0 lays out while and for, is rearranged to jump to the test once, on entry, and test at the bottom. Each iteration of the loop then executes one conditional jump instead of a conditional and an unconditional one.

comjump (10138–10172) does another kind of merging: when two unconditional jumps go to the same place and are preceded by the same instructions, the instructions are kept in one place and the other jump is redirected to them.

jumpsw (10346–10372) numbers every node in order, storing the numbers in the refc field, which is no longer needed for reference counts at that point. It uses the numbers as positions: when a conditional jump is followed by an unconditional one, and the conditional's target is further away, the two are swapped and the condition reversed. The assembler can turn a conditional jump to a nearby label into a single short branch, but must use two instructions for a distant one, so it pays to give the conditional the nearer target.

Finally addsob (10374–10392) uses the same positions. The PDP-11/40 and later models have sob, “subtract one and branch if not zero”, which does in one instruction what dec r; jne L does in two, but can only branch backwards, and not far. addsob makes the replacement when the label comes earlier and is less than 50 lines back. In loop.c, do *p++ = 0; while (--n); becomes a two-instruction loop:

L4:clr	(r4)+
sob	r3,L4

Remembering registers

rmove (10207–10344) is the most intricate routine in c2. It walks through the code keeping, for each register, a string saying what the register is known to hold: regs[r] might be -10(r5) after mov -10(r5),r1, or $0 after clr r1. Any label or unconditional jump clears everything, since control may arrive from elsewhere; a conditional jump forgets only the condition codes. Any instruction that writes to a location clears the registers that held it, and one that writes through a pointer clears everything that might be in memory, since the pointer could point anywhere (10495–10516). With this information it:

  • deletes a mov into a register that already holds the value;
  • replaces an operand with a register known to hold the same value, which gives a shorter instruction, or a faster one (repladdr, 10604–10644); this is the “simplified addresses” count, and it is how mul -10(r5),r1 in sum.c became mul r1,r1;
  • deletes a tst of a location whose condition codes were just set by the previous instruction, remembered in ccloc;
  • and, in redunbr, decides some conditional jumps at compile time.

The last needs a word. setcon remembers one location known to hold a constant, in conloc and conval. When an unconditional jump leads to a comparison of that location with a constant, followed by a conditional jump, redunbr (10694–10724) evaluates the comparison itself and, if the branch would be taken, sends the first jump straight to its target. In sum.c, after loop inversion, the loop starts with i just set to 0 and a jump to the test i < 10. c2 works out that the test succeeds, and jumps directly into the loop body; the jump to the test is then a jump to the next instruction, and disappears. The optimized sum has no jump at all on entry to the loop.

redunbr has a bug that happens not to matter. Its parameter is ap, but the body uses a register variable p that is never assigned:

c21.c
10694  redunbr(ap)
10695  struct node *ap;
10696  {
10697          register struct node *p, *p1;
10698          register char *ap1;
10699          char *ap2;
10700  
10701          if ((p1 = p->ref) == 0)
10702                  return;

It works because p is the first register variable in redunbr, so it lives in r4, and the caller, rmove, also keeps its p in r4 (10209). csv saves r4 but does not clear it, so on entry redunbr's p still holds the caller's, which is the very node that was passed as ap.

A tip of the hat

The last improvement is made as each instruction is printed. reducelit (9795–9822) looks for an immediate operand followed by an indexed one with the same number:

mov	$6,6(r0)

An immediate operand is stored in the word after the instruction and addressed as (pc)+. The index of the second operand is stored in the word after that. If the two words are equal, the first operand can be made to refer to the second word instead, by addressing it as (pc), without the increment, and one word of the instruction disappears:

mov	(pc),6(r0)

The comment credits the idea to BLISS-11, the Carnegie-Mellon compiler for the PDP-11 whose object code was the standard of the time: “Thanx and a tip of the Hatlo hat to Bliss-11”. (Jimmy Hatlo drew the newspaper cartoon They'll Do It Every Time, which ended with a tip of his hat to the reader who sent in the idea.)

What c2 does not know

c2 decides which labels are used by looking at jump instructions and the entries of switch tables. It does not look at other operands. So a label whose address is taken, as in the computed goto of chapter 8, looks unused. refcount deletes it, and then the code after the jmp that should reach it looks unreachable, and iterate deletes that too. With -O, cgoto.c loses everything after its first goto, and the reference to the deleted label is left dangling:

% cc -O cgoto.c; a.out
Undefined:
L2
a.out: not found

Computed goto was so rarely used that this can hardly have been noticed. It shows the limit of a program that improves code without knowing what it means.
